## What to build

Повторное ревью перестаёт отвечать на открытый вопрос «какие есть проблемы?»
и становится фазой верификации, отвечающей на закрытый: «устранено ли каждое
исходное замечание?». Модуль разбора замечаний получает вторую схему —
вердикты верификации: массив записей, позиционно сопоставленных исходным
блокирующим замечаниям, каждая — «устранено» или «не устранено» плюс
строковое обоснование. Промпт верификации передаёт исходные блокирующие
замечания дословно и требует вердикт по каждому; контракт файла вердиктов
(путь, схему, запрет менять worktree) раннер добавляет поверх редактируемого
шаблона, имя шаблона фазы сохраняется, чтобы существующие переопределения
продолжили применяться. Цикл попытки сравнивает вердикты с исходным
множеством: все устранены — попытка принимается без дополнительных кругов
ревью; массив неверной длины или записи неверной формы — провал этапа
верификации; есть неустранённые — попытка отклоняется (сужение фронта по
раундам — следующий тикет). Новых блокирующих замечаний в схеме вердиктов не
существует по построению, поэтому цикл структурно монотонен.

## Acceptance criteria

- [ ] После исправления фаза верификации получает исходные блокирующие
      замечания дословно и выносит вердикт по каждому.
- [ ] Вердикты «все устранены» принимают попытку; последующего поиска новых
      проблем не происходит.
- [ ] Файл вердиктов неверной длины или с записью неверной формы проваливает
      этап верификации с внятным итогом.
- [ ] Вердикт «не устранено» отклоняет попытку.
- [ ] Существующее переопределение шаблона фазы повторного ревью применяется
      к промпту верификации без переименования файла шаблона.
- [ ] Промпт и итоги следуют настроенному языку.
