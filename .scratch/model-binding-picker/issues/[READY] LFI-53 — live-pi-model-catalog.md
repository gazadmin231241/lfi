## What to build

Выбрав в экране привязок агента `pi`, пользователь видит его настоящие модели
списком, а не пустоту с одним пунктом ручного ввода.

Каталог берётся у самого `pi`: он единственный из четырёх агентов умеет
перечислять модели. Машиночитаемого вывода у этой команды нет — флаг `--json`
она молча игнорирует, а режим json относится к выводу сессии, — поэтому
разбирается печатаемая таблица с колонками провайдера, модели, размера
контекста, лимита вывода, поддержки размышлений и изображений.

Файлы каталога в профиле `pi` намеренно не читаются. По отдельности они
неполны: часть провайдеров лежит в одном, часть в другом, часть встроена, и
правильный список получается только их слиянием, которое умеет один `pi`.
Разбор колонок хрупок, но хрупок явно: при смене формата мы получим пустой
список и уйдём в ручной ввод, а не тихо покажем половину моделей.

Вызов ленивый — он происходит в момент выбора `pi`, а не при старте команды — и
ограничен тайм-аутом. Отсутствие команды на хосте, тайм-аут, ненулевой код
возврата и нераспознанный вывод ведут к одному и тому же: ручной ввод и одна
строка, объясняющая, почему списка нет. Инициализация проекта не падает
из-за недоступного каталога одного из четырёх агентов.

## Acceptance criteria

- [ ] Выбор `pi` показывает модели, перечисленные самим `pi`, в виде
      `<провайдер>/<модель>`.
- [ ] Пункт «своя модель…» остаётся доступен вместе с каталогом.
- [ ] Каталог запрашивается только при выборе `pi` и ограничен тайм-аутом.
- [ ] Отсутствие команды, тайм-аут, ненулевой код возврата и нераспознанный
      вывод уводят в ручной ввод с объяснением, не прерывая `lfi init`.
- [ ] Разбор вывода — чистая функция, покрытая тестами на нормальную таблицу,
      пустой вывод и мусор, без запуска процесса.
- [ ] Файлы каталога из профиля `pi` не читаются.
