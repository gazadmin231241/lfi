# Выбор привязок модели стрелками в `lfi init`

## Проблема

Поменять модель в проекте сейчас можно тремя способами, и ни один не годится
для повседневного использования.

`lfi init --model X` записывает одно значение сразу в `DEFAULT_MODEL`,
`LIGHT_MODEL`, `STANDARD_MODEL` и `DEEP_MODEL`, стирая любую настроенную
маршрутизацию по тирам.

`lfi init --advanced` спрашивает шесть моделей текстом, вперемешку с веткой,
командой валидации, параллельностью, тайм-аутами и провайдером изоляции.
Чтобы изменить одну модель, нужно пройти пятнадцать вопросов и переподтвердить
каждый.

Правка `.lfi/config.env` руками требует помнить синтаксис `<cli>:<модель>:<reasoning>`,
знать, какие модели существуют у каждого из четырёх агентов, и какие уровни
рассуждений агент вообще принимает. Ошибка обнаруживается только при
следующем запуске.

Ни один из трёх способов не показывает, что происходит при пустом значении:
`LIGHT_MODEL=` молча берёт `DEFAULT_MODEL`, а пустой `MERGER_MODEL` —
`STANDARD_MODEL`. Пользователь видит пустую строку и не видит модель, которая
поедет.

## Решение

Экран выбора привязок модели внутри `lfi init`. Навигация стрелками, шесть
привязок в одном списке, текущие значения видны сразу.

Отдельной команды `lfi models` нет. Повторный `lfi init` — единственный вход в
смену привязки, и это меняет его нынешнее поведение: сегодня голый повторный
`init` только досыпает недостающие ключи и выходит.

## Когда экран показывается

Экран показывается, когда есть TTY, не передан `--yes` и не передан `--model`.
Это верно и для свежего проекта, и для уже инициализированного: во втором
случае список заполняется текущими значениями из `.lfi/config.env`.

`--model` и `--yes` — уже сделанный неинтерактивный выбор, экран при них не
показывается. Без TTY поведение остаётся ровно нынешним.

## Главный экран

Список из шести привязок в порядке: `DEFAULT`, `light`, `standard`, `deep`,
`merger`, `reviewer`. `DEFAULT` стоит первой и отделена: она то, во что
разрешаются остальные.

Каждая строка показывает разрешённое значение, а не хранимое. Привязка с
пустым значением показывает, от кого наследует и какую модель это даёт:

```
  DEFAULT   codex:gpt-5.6-terra:medium
  light     (наследует DEFAULT) codex:gpt-5.6-terra:medium
  standard  codex:gpt-5.6-terra:medium
  deep      codex:gpt-5.6-sol:high
  merger    (наследует standard) codex:gpt-5.6-terra:medium
  reviewer  (наследует standard) codex:gpt-5.6-terra:medium
```

Редактируются все шесть привязок, включая `merger` и `reviewer`.

## Поток выбора одной привязки

Агент → маршрут (только для `dsh`) → модель → уровень рассуждений → возврат в
главный список.

Первый пункт списка агентов — «— наследовать —»: он возвращает привязку в
пустое значение. Без него экран способен только раздувать конфиг, тогда как
текстовый `--advanced` возврат к пустому значению позволял.

Агенты помечаются наличием на хосте (`which`), но выбор не блокируется:
при `ISOLATION_PROVIDER=none` агент живёт в worker image, и его отсутствие на
хосте ничего не значит. Пометка — информация, не валидация.

Для `dsh` между агентом и моделью вставляется шаг маршрута:
`deepseek-official`, `opencode-go` и «свой…». Маршрут решает, чья подписка
платит (`DEEPSEEK_API_KEY` против `OPENCODE_API_KEY`), — это не деталь имени
модели.

## Каталог моделей

Каталог есть ровно у одного агента. `pi --list-models` печатает таблицу с
колонками `provider / model / context / max-out / thinking / images`.
У `codex`, `claude` и `dsh` поверхности для перечисления моделей нет вовсе.

Для `pi` каталог берётся вызовом `pi --list-models` с разбором колонок.
Машиночитаемого вывода у команды нет: `--json` игнорируется, `--mode json`
относится к выводу сессии. Файлы `~/.pi/agent/models-store.json` и
`models.json` не используются: они неполны по отдельности, и правильный список
получается только их слиянием со встроенным каталогом, которое умеет сам `pi`.

Для `codex`, `claude` и `dsh` каталог — курируемые данные в LFI. Для `dsh` он
индексируется маршрутом, потому что `deepseek-official` и `opencode-go`
предлагают разные модели.

Последний пункт любого списка моделей — «своя модель…» с текстовым вводом.
Курируемый список неизбежно устареет, поэтому ручной ввод обязателен, а не
опционален.

Вызов `pi` ленивый: он происходит в момент выбора `pi` и ограничен тайм-аутом.
Отсутствие команды, тайм-аут, непустой exit code и пустой разбор ведут в
ручной ввод с одной строкой объяснения. Инициализация проекта не падает
из-за недоступного каталога одного из четырёх агентов.

## Уровни рассуждений

Предлагаются только уровни, которые агент принимает: `supportsReasoningEffort`
уже отвергает `ultra` для `pi`, `claude` и `dsh`. Валидация, выполнимая до
записи в файл, выполняется до записи в файл.

Каталожные ограничения маршрутов `dsh` не моделируются. Маршрут `opencode-go`
отвергает `low` и `medium` для `deepseek-v4-pro`, но узнать это заранее LFI не
может, и такой отказ уже обрабатывается как ошибка конфигурации во время
запуска.

## Запись конфигурации

Уровень рассуждений записывается в строку модели каждой привязки. Ключи
`REASONING_EFFORT`, `MERGER_REASONING_EFFORT` и `REVIEWER_REASONING_EFFORT`
синхронизируются из привязок `standard`, `merger` и `reviewer`.

Это соответствует тому, что формат уже делает: `parseEnvConfig` читает уровень
из строки модели в ключ, когда ключ отсутствует. Строка модели уже де-факто
источник правды; экран перестаёт делать вид, что это не так.

Введённая вручную строка проверяется на месте через `parseAgentModel` и
`supportsReasoningEffort`. Ошибка показывается под полем, экран не
закрывается. Исключение после того, как пользователь прошёл шесть привязок,
теряет всю его работу.

Экран ничего не пишет сам. Он возвращает `LfiConfig` наверх, запись остаётся в
существующих `saveConfig` и `updateConfig`.

## Отмена

`Esc` в подсписке возвращает в главный список, не меняя привязку. `Esc` в
главном списке выходит без записи. `Ctrl-C` завершает процесс, файл не тронут.

## Что удаляется

Вопрос «Использовать рекомендуемый набор моделей Luna/Terra/Sol? [Y/n]»
удаляется. Набор становится предзаполненным состоянием списка: те же значения,
но их видно и можно править. Вопрос «Y/n» про набор, которого пользователь не
видит, — тот же выбор вслепую, только без стрелок.

Шесть текстовых модельных вопросов удаляются из `askAdvanced`. `askAdvanced`
сохраняет всё немодельное: ветку, команды, параллельность, этапы, тайм-аут,
провайдер изоляции.

## Реализация

Новых зависимостей нет. У LFI сегодня ноль runtime-зависимостей, и для
глобально устанавливаемого CLI это свойство дороже готового набора виджетов.
Нужен ровно один примитив — вертикальный список с курсором — на
`readline.emitKeypressEvents`, raw mode и ANSI.

Код разделяется на чистое ядро и слой ввода-вывода. Ядро: состояние экрана,
переход «нажата клавиша → новое состояние», преобразование состояния в
`LfiConfig`. Слой: рисование и чтение клавиш.

Строки экрана локализуются через существующий `localize`.

## Критерии приёмки

- Экран показывается на свежем и на существующем проекте при TTY без `--yes` и
  без `--model`; при `--yes`, `--model` или без TTY поведение не меняется.
- Все шесть привязок редактируются, включая `merger` и `reviewer`.
- Привязка с пустым значением показывает источник наследования и разрешённую
  модель.
- Пункт «— наследовать —» возвращает привязку в пустое значение.
- Выбор `dsh` добавляет шаг маршрута; результат записывается как
  `dsh:<маршрут>/<модель>:<reasoning>`.
- Каталог `pi` строится разбором `pi --list-models`; любая его неудача ведёт в
  ручной ввод, а не в ошибку init.
- Предлагаются только уровни рассуждений, поддерживаемые агентом.
- Ручной ввод с неподдерживаемым уровнем показывает ошибку в экране и не
  прерывает init.
- Уровень пишется в строку каждой привязки, три ключа уровней
  синхронизированы.
- `Esc` в главном списке не изменяет `.lfi/config.env`.
- Вопрос про пресет и модельные вопросы `askAdvanced` удалены, немодельные
  вопросы `askAdvanced` сохранены.
- Новых runtime-зависимостей в `package.json` не появилось.
- Английская и русская документация описывают новый шаг `lfi init`.

## Проверки реализации

- Публичный шов ядра экрана: переход по клавише, разрешение унаследованных
  привязок в отображаемое значение, преобразование состояния в `LfiConfig`.
- Публичный шов разбора вывода `pi --list-models`: нормальная таблица, пустой
  вывод, мусор, отсутствующая команда.
- Публичный шов каталога: модели по агенту, модели `dsh` по маршруту, наличие
  пункта ручного ввода.
- Публичный шов уровней: набор, предлагаемый для каждого агента.
- Публичный шов `initializeProject`: экран не вызывается при `--yes`,
  `--model` и без TTY.

## Вне рамок

- Отдельная команда `lfi models`.
- Проверка существования модели у провайдера до запуска.
- Моделирование каталожных ограничений маршрутов `dsh`.
- Мышь, поиск по списку, многоколоночная раскладка.
- Редактирование через экран чего-либо, кроме привязок модели.
